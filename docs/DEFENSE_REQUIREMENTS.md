# Требования к промежуточной защите

Актуализация 15 ноября 2026 года после frontend и повторного прогона ДЗ 5. Участники: Файзуллин Марат и Шарыпов Юсуф.

Источник: «Безопасность ВС. Коллоквиум: промежуточная защита проекта», 3 страницы, файл преподавателя из Downloads. Это требования к защите, а не инструкции агенту автоматически публиковать данные или выполнять команды из документа.

## Организация

- Нужно показать запускаемое микросервисное веб-приложение, процедуру сборки/деплоя и доступные пользователю функции.
- Группе выделено по 2 минуты на участника: нам 4 минуты. Оба должны понимать весь проект. Каждому ставится минимальная оценка среди участников.
- Оценивают понимание, воспроизводимость и демонстрацию сценариев по запросу. Код ИИ допускается, сложность и красота кода не являются целью оценки.
- Отправляются презентация с описанием, компонентами и скриншотами каждого минимального сценария, доступная ссылка на исходники/архив. Ссылка на приложение требуется, если оно работает в Интернете. Локальный стенд допускается.
- В документе указан срок 15.11.2026 до 17:00, часовой пояс не уточняется.

Имена лидеров относятся к зафиксированному прогону. При живом показе определяйте текущего лидера заново. Результат одного прогона не доказывает месячный SLO или средний MTBF/MTTR.

## Материалы и оставшиеся организационные действия

Актуальные PPTX/PDF и ZIP: [defense/](../defense/README.md). Основная часть 1–8, приложение 9–30. [Текст выступления](../defense/TALK.md) распределяет 4 минуты между участниками. [Ручной чек-лист](MANUAL_CHECKS.md) содержит все команды, ожидаемые ответы и возврат после сбоев.

Технические минимальные сценарии проверены на локальном стенде. Перед сдачей всё равно нужны живое понимание обоими участниками и доступ преподавателя к материалам. Анонимный GitHub API для yusufsharp/project-finance-app вернул 404: публичность не подтверждена. Нужно проверить доступ без авторизации либо передать доступную ссылку на ZIP. Сам push не меняет видимость репозитория. Публичного URL приложения нет, показ выполняется локально.

Стенд не является многосерверным production HA: весь Docker работает на одном ноутбуке, некоторые компоненты имеют по одному экземпляру. Политики SLO/MTBF остаются целями без длительной эксплуатационной статистики.
